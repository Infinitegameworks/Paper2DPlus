# Paper2DPlus — Developer Onboarding

Paper2DPlus is a UE 5.0–5.8 plugin for Paper2D character profiles, layer-aware art and gameplay data, behavior-carrying Frame Cues, combat advice, visual effect libraries, character cataloging, and optional multiplayer/runtime-appearance support. LostRadiance currently targets UE 5.8; UE 5.7 remains a supported build gate.

## Quick Start

1. The plugin's canonical source is the `Paper2DPlusDev` repository (plugin at repo root); game projects such as LostRadiance and BloodJunkies consume it as a git submodule at `Plugins/Paper2DPlus/`.
2. `Paper2DPlus` is the cooked runtime module. `Paper2DPlusBlueprintNodes` is an UncookedOnly module for runtime-Blueprint-safe custom K2 nodes. `Paper2DPlusEditor` contains authoring, migration, validation, bake, preview, and custom pin UI.
3. Read the repo-root `AGENTS.md` or `CLAUDE.md` for the complete source-file map, build gates, and agent conventions. Those two files must remain synchronized.
4. Start designer-facing work with [Paper2DPlus Designer Guide](docs/designer-guide.md).
5. The LostRadiance host repository currently contains 51 pattern docs under its `docs/solutions/` (50 at the top level plus 1 under `editor-patterns/`) and 4 plugin-local solution docs under `Plugins/Paper2DPlus/docs/solutions/` (pixel draw, runtime sprite offsets, plugin-shipped tag sources, Aseprite import & live-reimport).

## Architecture Overview

### Runtime module

| Area | Primary types | Contract |
|---|---|---|
| Character data | `UPaper2DPlusCharacterProfileAsset`, `FFlipbookProfileEntry` | Owns logical animations, optional sparse 3–16-slot multidirectional flipbook sets, hitboxes, sockets, root motion, curves, tags, transitions, and authoritative Frame Cue placements. Directional variants alias one base identity and contribute art plus a per-slot mirrored-presentation flag (re-picking a slot's art preserves it; the game applies the flip). Variant compatibility blocks only on the trim-invariant frame space — untrimmed canvas, pivot in that canvas, pixels-per-unit, rotation — while trim-rectangle/render-bounds drift is an advisory validation Warning. |
| Directional animation queries | `UPaper2DPlusDirectionalAnimationLibrary` | Seven cooked Blueprint operations: pure occupancy detection (`Has Multi Direction`); exact PaperZD-sign-compatible sector resolution from a non-zero `FVector2D` returning art, slot index, and the slot's mirrored-presentation flag (`Resolve Directional Flipbook` — its Direction Unoccupied failure keeps reporting WHICH sector resolved empty); the deliberately impure loading enumeration `Get Occupied Direction Slots` (index/flipbook/mirror records, also the warm/preload step); and the load-free topology reads `Get Direction Settings`, `Get Occupied Direction Slot Indices`, `Resolve Direction Slot Index`, and `Make Direction From Bearing`, which together let a project implement its own nearest/base/hold fallback. Base or owned-variant inputs resolve the same logical owner; configured-empty returns base, while an exact empty sector in a populated set fails without fallback; applying a mirrored slot's horizontal flip stays project-owned. No PaperZD type or playback dependency enters the surface. |
| Playback bridge | `UPaper2DPlusFlipbookComponent`, `UPaper2DPlusCharacterProfileComponent`, `Paper2DPlusFrameGeometry` | Emits flipbook/key-frame/start/terminal changes, applies root motion, composes equipped layer gameplay data, and for every admitted Frame Cue runs the cue's own behavior and then broadcasts to listeners (`NotifyFrameCue`, behavior-before-listener at every site). `SetFrameCuePlaybackSource` atomically binds the live Paper component. Custom-component observation is event-driven; a cue-carrying Profile or equipped Layer raises stock-component observation to every frame while a cue-free one keeps the 20 Hz watch. Natural completion evaluates the final frame before one `Completed` End; manual stop emits one `PlaybackStopped` End. PaperZD/game-owned timelines use `BeginExternalFrameCuePlayback` plus generation-scoped `ReportFrameCuePlaybackCompleted` / `ReportFrameCuePlaybackStopped`; these never control playback, and stop-then-play entirely between observations requires this explicit seam. Opt-in automatic hit detection (`bAutoHitDetection`, TASK-145) arms from attack-box frames, queries `UPaper2DPlusHitboxSubsystem` at frame entry plus the subsystem's armed-set tick, dedupes per victim/move-instance/hit-window, and broadcasts `OnHitConnected`/`OnHitReceived`/window-edge/whiff events on the adjudicating machine — receivers apply damage. Shared geometry keeps runtime collision and Combat Lab pivot/facing/root-motion projection identical. |
| Frame Cues | `UPaper2DPlusCueBase`, `UPaper2DPlusCue`, `UPaper2DPlusCueState`, `UPaper2DPlusSpawnFlipbookCue`, `Paper2DPlusFrameCues::DispatchFrameTransition`, `UPaper2DPlusFrameCueListener` | Cue objects carry reflected payload **and** their own overridable behavior: `OnCueTriggered` (Cue), `OnCueBegin`/`OnCueUpdate`/`OnCueEnd` (Cue State), all BlueprintNativeEvents with empty native defaults. Every Context directly snapshots the exact `CharacterProfile`, live `PlaybackComponent`, and `EPaper2DPlusFrameCueEvaluationMode`; no PaperZD AnimInstance is required. `ResolveFrameCueAnchor` returns Render Origin or a deterministic base/compiled Profile Socket world transform plus a keep-world attachment source and explicit failure result. Profile Socket never means a Layer-child/effective socket. `Paper2DPlusFrameCueBehavior::ExecuteCueBehavior` is the ONE phase-to-event mapping, shared by game dispatch and editor preview, and it self-gates on `IsPlacementResolvable`. Behavior runs synchronously on the SHARED asset-owned placement, so it must never write instance state; one recursive editor policy rejects latent/async/timer/deferred graph content at compile, readiness, save, durable validation, and cook. Receivers still own persistent state. **v8.0.0 deleted the six former native built-in Cue classes** (no migration, no CoreRedirects) **and ships exactly ONE native concrete cue in their place: `UPaper2DPlusSpawnFlipbookCue`** — a one-shot flipbook effect (soft warmed art, frozen `CosmeticOnly` class default, self-destroying `UPaper2DPlusEffectFlipbookComponent`, pure `ComputeEffectWorldTransform` placement math) whose authored Offset is draggable directly in the Frame Cues preview viewport. The three bases stay `UCLASS(Abstract)`; every other designer-placeable Cue is a designer-authored Cue Type — never `NewObject` a base as a stand-in, it compiles and then asserts. Editor-only `HideDropdown` automation/visual-tour fixtures are excluded from designer lists and cooked data. Fresh designer Cue Types receive the replaceable native `Paper2DPlus.Cue.Default` identity on their generated defaults only; native base CDOs remain untagged. The Character component warms and retains only the current animation's cue effects before traversal, discovering them through the overridable `CollectWarmableEffectArt` rather than by class — the structural scan reads top-level scalar soft flipbook properties on native and Blueprint cues alike. Moment cues carry a per-placement `TriggerEdge` (FrameStart legacy default; FrameEnd = trailing-boundary crossing via `WasFrameTrailingEdgeCrossed`, with natural completion fired from the profile component's Completed terminal drain and cut-short frames deliberately silent); it is placement timing — timeline-owned via the draggable anchor diamond, excluded from the durable Cue Type schema. |
| Character layers | `UPaper2DPlusCharacterLayerAsset`, `Paper2DPlusLayerBakeTypes`, `Paper2DPlusAppearanceResolver` | Schema-v5 generic Layers with cooked stable IDs, one global order, optional Exclusive Groups, complete Appearance Presets, one required Default Appearance, Layer-owned gameplay, two exclusive delivery modes, and editor-only bake evidence. Runtime Customizable publishes an edit/save-built cooked gameplay projection; Fixed / Baked compiles the default and clears the runtime projection. |
| Runtime appearance authority | `FPaper2DPlusAppearanceDescriptor`, `Paper2DPlusAppearanceResolver`, `UPaper2DPlusLayerRenderComponent`, `UPaper2DPlusAppearanceLibrary` | One deterministic committed descriptor feeds gameplay composition, SaveGame, replication, and the selected renderer. `UPaper2DPlusAppearanceLibrary` is the Blueprint discovery and swap surface: it describes Layers, Exclusive-Group slots and Presets by id and name (from the asset alone or from a live component) and cycles/selects/toggles them through the component's committed setters, never a parallel path. |
| Hybrid presentation | `FPaper2DPlusAppearanceRenderPolicy`, `Paper2DPlusSpriteMaterialContract`, render backend, transient composite cache, `UPaper2DPlusAppearanceBudgetSubsystem` | Client-local GPU composites over cooked sprite triangles, bounded exact-order live handoff, one-time immutable recipe admission, one world scheduler, no persistent appearance assets. |
| Character catalog | `UPaper2DPlusCharacterCatalogAsset` | Cook-safe, soft-first character roster, companion assignments, requirements, tags, groups, expected-animation declarations, and read-only queries. |
| Effect library | `UPaper2DPlusEffectProfileAsset` | Ordered, soft-first flipbook membership plus Type/Descriptor classification. Loading the Profile loads no effect art; metadata/path queries are no-load and resolving output Flipbooks is the explicit per-result loading boundary. Blueprint receives hard Flipbook outputs and never sees raw soft row storage. |
| Combat advice | `UPaper2DPlusCombatProfileAsset`, `UPaper2DPlusCombatProfileComponent`, `FPaper2DPlusCombatScoring` | Derives physical facts from a Character Profile and returns ranked utility advice; variable maps are sparse overrides with an explicit legacy-inheritance review; never plays attacks or applies damage. |
| Network/debug | `Paper2DPlusNetGating`, `Paper2DPlusNetTypes`, `UPaper2DPlusDebugComponent`, `Paper2DPlusDebugOverlay` | Opt-in authority gates, compact intent replication, and diagnostics. Single-player remains the default. |

## Ownership Model

| Asset or surface | Owns | Does not own |
|---|---|---|
| Character Profile | Animation identity/timing, character-wide hitboxes/sockets/Cues, curves, root motion, tags, From→To transitions | State-machine playback, damage, Cue side effects |
| Character Layer Asset | Generic Layer art/global order/placement, optional Exclusive Groups, complete presets/default, Layer-specific boxes/sockets/Cues, delivery/bake metadata | Project-wide character relationships, AI decisions |
| Effect Profile | Ordered visual flipbook library and Type/Descriptor tags | Spawn placement or behavior, character relationship authority |
| Combat Profile | Tactical tuning, variables, score profiles/presets, ranked explanations | Physical attack truth, playback, damage, cooldown enforcement |
| Character Catalog | Saved roster, companion assignments/requirements, character tags, explicit groups, base/per-group expected Animation Tags | Actor classes, spawning, encounter selection |
| Game Blueprint/C++ | Playback, gameplay effects, Cue receivers, server RPCs, encounter/AI state, persistence policy | Shared authored asset mutation at runtime |

## Core Workflows and Concepts

### Character Profile workspace

The workspace layout key is `CharacterProfileAssetEditor_Layout_v15_ExpectedTags`. A compact current-animation search/preview control sits above each of the six main tools. It shows the current loaded Flipbook, opens the compact search popup, and uses focused Up/Down to select adjacent animations without wrapping; persistent previous/next rows are intentionally absent. Popup and Navigator rows render loaded flipbooks through the shared hover thumbnail without synchronously loading unloaded assets. The virtualized dockable **Navigator** starts closed so large animation catalogs do not permanently consume horizontal space; its saved dock placement is retained. Details and the profile-wide **Expected Tags** checklist share the upper-right stack, with Details foreground by default. Selection remains stable while switching tools, reorder, undo, or external refresh.

The center stack contains:

- **Animations** — Grid/List/Map views over the same selection and details, selected through one **View** menu in the shared current-animation header. Grid/List uses one compact browse bar; Map is a transient write-through projection of flat From→To transition data with a canvas tool rail rather than a second permanent toolbar row.
- **Hitbox Editor** — character-wide attack/hurt boxes and sockets.
- **Sprite Editor** — extraction offsets and sprite work.
- **Frame Timing** — definitive Paper2D key-frame duration editing.
- **Frame Cues** — an always-visible unified timeline with the implicit Default and optional named Cue tracks, top **+ Add Cue / + Add Curve** actions plus a **Manage tracks...** overflow that owns every track command (the persistent **+ Add Track** button is retired), a counted **Remove all** recovery notice when literal null placement slots exist, and Profile-owned curves inline below on the same frame axis.
- **Root Motion** — per-key-frame motion path.

The Map view projects ordinary Profile-local animation groups and From→To transition rows. Open **Full Map** from the group board to author transitions across groups; scoped group graphs remain the focused place for chain-marker authoring. Node positions persist as editor-only Profile data, while the flat transition and tag-mapping arrays remain the source of truth.

Sprite alignment is permanent Profile-owned authored data. Editor previews and runtime rendering consume `FrameExtractionInfo.SpriteOffset + TrimOffset` automatically; there is no separate Apply/save step or offset-specific close warning, and the editor never bakes those values by mutating a shared `UPaperSprite` pivot. The former `bHasCustomAlignment` marker is a soft-deprecated loading-only compatibility field, not an alignment gate or second source of truth. Character Profile close first settles active tool gestures, then uses Unreal's normal dirty-package handling (TASK-126/TASK-127.3).

The secondary **Character Data → Character → Sprite Bounds** category performs an explicit read-only check across every Profile flipbook. Each animation derives one uniform target from its maximum directional content extents around the authoritative frame anchors; blank frames are reported but do not inflate the maximum. It is VERIFY-ONLY: there is no repair action, and attention rows route to **Re-extract**. Reports carry `AttentionFrames` (repairable plus unsupported), every diagnostic reaches the user regardless of frame classification, and the scan runs only on an explicit action with a distinct in-progress state. Out-of-region, conflicting shared-sprite, and cross-Profile shared-sprite cases are reported as unsupported. `RepairProfile` is retained but exposed nowhere: re-extraction does not cover its pivot baking, `TrimOffset` clearing, `SpriteOffset` preservation, or its two fail-closed refusals.

Validation is a compact action, not a seventh main tool. It opens the shared modeless issue panel with read-only issues and truthful navigation targets, then gets out of the way when closed.

`SProfileToolPanelHost` owns the right-side Details categories for the active tool. It renders every available provider descriptor in order inside one vertical scroll surface, persists expanded/collapsed state independently per tool, expands and reveals categories for explicit focus requests, and defers structural switches outside tab activation callbacks. Sprite's **Onion & Skins** category places the colored Onion / Forward / Reference channels directly in that surface as a vertical stack of shared property rows — the same control Root Motion's Onion & Skins category uses — and it is not another dropdown. The legacy embedded Sprite layout alone wraps the same shared widget in its compact toolbar menu. `SCharacterCompletionPanel` tracks the selected animation's Hitboxes, Alignment, Timing, Motion, and Tags criteria. **Related Profiles** is a sibling dock tab in the same lower-right stack, so relationship navigation remains available without a permanent header above the authoring surface. It projects the Catalog relationship but never becomes another relationship authority. **Playback Queue** (`SPlaybackQueuePanel`) is the third sibling in that stack: an ordered preview playlist with transport controls, drag-to-add and drag-to-reorder rows. Queue state lives on the shared model — this panel owns only the UI and the playback ticker, which drives the model's flipbook/frame selection so every tool tab follows through the ordinary selection delegates.

Layer, Effect, and Combat use `SProfileCompletionPanel` with persisted editor-only flags and explicit undoable transactions. Their criteria are Layer (**Structure, Art, Hitboxes, Frame Cues, Publishing**), Effect (**Library, Classification, Preview, Placement, Validation**), and Combat (**Setup, Attack Tuning, Variables / Defaults, Scoring, Scenario Testing**). All four profile types export a hidden done/total asset-registry pair through `Paper2DPlusAuthoringProgressTags.h`, and `SProfileCompletionPanel::AllCriteriaMask` DERIVES from `ProfileChecklistCriteriaMask` so the checkbox list cannot disagree with the exported total. The Character Catalog roster consumes that pair per character — the Character Profile plus each assigned companion, resident object first then registry tags, with no synchronous load. Because the criteria are manual ticks with no content-derived fallback and the tags refresh only on SAVE, an absent or malformed pair is an explicit "no data" state and is never presented as complete.

### Frame Cues, not executable Frame Events

Current authoring uses `UPaper2DPlusCueBase` subclasses:

- a **Cue** broadcasts `Trigger` when traversal crosses one anchor;
- a **Cue State** broadcasts `Begin`, optional `Update`, and paired `End` across a half-open span.

`UPaper2DPlusCueBase` is hidden and abstract; the two designer parent classes are
`UPaper2DPlusCue` and `UPaper2DPlusCueState`. Content saved with the retired
`UPaper2DPlusFrameCue`, `UPaper2DPlusMomentCue`, or `UPaper2DPlusRangeCue` names loads through
three direct plugin-local CoreRedirects. Cue Type durable schemas deliberately keep those legacy path tokens
in canonical text so an existing baseline and fingerprint remain byte-identical; loading never restages or
dirties the asset.

**A Cue Type may now implement its own behavior.** This is a DELIBERATE, user-approved reversal of the previous "Frame Cues are data, receivers own behavior" rule shipped in v8.0.0 — not drift, and not something to "fix" back. `UPaper2DPlusCue` declares `OnCueTriggered`; `UPaper2DPlusCueState` declares `OnCueBegin`, `OnCueUpdate`, and `OnCueEnd`. All four are BlueprintNativeEvents with empty native default bodies, so a payload-only Cue Type behaves exactly as it did before. `Paper2DPlusFrameCueBehavior` in `Paper2DPlusFrameCue.h` is the single authority: it owns the declared-event name lists, the seed list for new types, `IsPlacementResolvable`, and `ExecuteCueBehavior` — the one Cue/Cue State x phase mapping shared by runtime dispatch and editor preview. Add a behavior event by declaring it there once; every envelope layer and the restricted authoring surface read the same list.

**Behavior is stateless by contract.** It executes on the SHARED asset-owned placement instance — two components dispatching the same placement call the same object — so an implementation must read the placement's payload plus the context, act on the world, and never write instance state. Persistent state stays on the receiver/actor. This is pinned by test.

The Character Profile Component funnels runtime delivery through `Paper2DPlusFrameCues::DispatchFrameTransition` (declared in `Paper2DPlusFrameCueDispatch.h`). `UPaper2DPlusCharacterProfileComponent::NotifyFrameCue` is the one sink: it runs `ExecuteCueBehavior` and THEN broadcasts `OnFrameCue` — the cue acts, then the world reacts — at every site, including the EndPlay/`ComponentDestroyed`, animation-change, and wardrobe force-end paths. `UPaper2DPlusFrameCueListener` and the dedicated **Listen for Frame Cue** node expose typed lifecycle outputs unchanged.

Every Begin is paired with a listener End at every teardown boundary (frame change, EndPlay/ComponentDestroyed, AnimationChanged, wardrobe sweep, stale sweep). **A LOOP WRAP IS NOT ONE.** A range that still contains the post-wrap frame stays active and receives only its ordinary Update — no End, no second Begin — so a range authored across a whole looping animation is ONE continuous range instead of an End/Begin pair every cycle (`Paper2DPlus.FrameCues.Behavior.LoopSeamKeepsBehaviorContinuous` pins it); only a range that no longer covers the post-wrap frame takes the `LoopReset` End. **One asymmetry is deliberate:** a range whose Cue Type CLASS died mid-flight still receives its listener End (force-end gates on `IsValid` so receiver-owned state is released) but receives NO behavior End, because `ExecuteCueBehavior` self-gates on `IsPlacementResolvable`. Consequence, and the reason it is safe: releases belong on receivers. Two more shapes to know: the End-only wardrobe sweep can deliver an `OnCueUpdate` to a still-present in-range cue with no frame change (`bWasActive` bypasses admission), and at a loop wrap an orphaned-but-alive range now ends `SourceRemoved` rather than `LoopReset`.

`UPaper2DPlusCueBase::PlayCueSound` is the context-aware sound helper (BlueprintCallable, additive in v8.0.0): in game it plays at the owning actor's location and refuses on a dedicated server; in editor preview it routes through the runtime-declared `SetPreviewSoundHandler` seam that the editor module binds at startup, so runtime never depends on editor code.

Reusable custom payloads use the dedicated **Paper2D+ Frame Cue Type** asset. Content Browser creation and the timeline's **+ New Frame Cue Type...** action both present only the guided Cue/Cue State choice—never Unreal's arbitrary Blueprint parent picker. The restricted editor hosts Unreal's stock **My Blueprint** panel for ordinary payload-variable browsing and operations, alongside one plugin-owned **Override** control that implements only the declared Cue events through the safe event-node path (including a wired parent call for designer-authored Cue parents). Its normal Blueprint toolbar exposes the protected Compile command, Diff, Find / Hide Unrelated, Class Defaults, and PIE/debug controls. The five allowlisted tool tabs are My Blueprint, Details, Class Defaults, Compiler Results, and Find Results; Class Settings, save-on-compile, Delete Unused Variables, and arbitrary function creation remain disabled. A quarantined legacy Cue Blueprint receives a warning/recovery body instead of My Blueprint, so forbidden graphs are never listed or deletable. The envelope still rejects, verbatim and at all four layers: function/macro/delegate-signature graphs, a second ubergraph page, any generated function that is not a declared event, components/construction scripts, timelines, interfaces, delegate payload fields, Blueprint getter/setter fields, replication/RepNotify fields, non-persistent field flags, and any generated field without a matching authored payload field. Ordinary Cue-derived Blueprints remain loadable through explicit legacy recovery without silently deleting their authored graphs.

`DurableSchemaVersion` is **2** (`FPaper2DPlusFrameCueTypeAuthoring::CurrentSchemaVersion`), with `BehaviorFreeSchemaVersion = 1` accepted verbatim: `DescribeSchema` stamps 1 and emits no `behavior;` lines when a type has no behavior events, so a payload-only Cue Type's canonical text and fingerprint are byte-identical to v1, and a v1-stamped durable baseline still classifies `Ready` without restaging. ### Mutually exclusive layer delivery modes

`ECharacterLayerUsageMode` selects exactly one renderer/data-delivery path:

| Mode | Intended use |
|---|---|
| Fixed / Baked | The Default Appearance is compiled into the registered flipbooks/Profile |
| Runtime Customizable | Blueprint selects generic Layer IDs or complete Appearance Presets at runtime |

Changing delivery mode is transactional. An asset that still owns fixed output—or is Recovery Required—must be repaired if needed and detached before enabling Runtime Customizable delivery. A renderer must never show both paths at once.

### Fixed publishing lifecycle

First adoption is one atomic **Adopt and Bake All**. It analyzes legacy ownership without mutation, captures Character Baseline and original flipbook registration source, resolves ambiguous rows through Suggested/Assign/Merge/Archive-only decisions, stages all output, then commits or rolls back as one operation.

Fixed publishing always overwrites the same Paper Flipbook objects. It preserves their identity/path, references, timing, key-frame count, and frame runs. It may maintain a bounded owner-stamped backing set of textures/sprites, but repeated identical bakes do not grow assets and removed source contributions do not remain stale.

The editor bake reads mip-zero `Texture.Source`, so exactness is proven before mutation for both registered canonical frames and included layer sprites. The accepted ordinary path is deliberately explicit: `TC_EditorIcon`, `TEXTUREGROUP_Pixels2D`, exactly `TF_Nearest`, exactly `TMGS_NoMipmaps`, zero LOD bias, default color adjustments and source-color metadata, and no alpha/gamma/channel/resize transform that could make rendered texels differ from source bytes. `Default` filtering and `FromTextureGroup` mip generation are rejected because inherited settings can change outside the asset. Ordinary source/output materials must be known stock Paper2D Surface materials using exactly the Unlit shading model and Opaque, Masked, or straight-alpha Translucent behavior. Atlas/rotated regions, additional source textures, alternate material sections, custom or mixed-shading materials, incompatible opacity flattening, and transformed texture builds fail closed with a corrective diagnostic.

Tight source sprites remain exact: bake rasterizes their cooked `BakedRenderData` triangle coverage before linear-space composition, includes that coverage plus material/texture-build state in digest version 4, and rejects geometry it cannot map exactly. Empty/incomplete triangle lists, non-finite or unmappable vertices, non-manifold edges, and an outer edge through a texel center fail closed rather than guessing the GPU fill rule. Managed output sprites rebuild render geometry to the full generated cell so expanded layer pixels cannot be clipped; collision geometry follows its separate translated preservation path, while pivot and pixels-per-unit semantics remain registered.

All canonical mutations go through `CharacterLayerBakeCoordinator`; do not write managed output from another path. Main actions are **Bake Current**, **Bake All**, **Save Bake Set**, **Overwrite from Layer Source**, **Rebase Registration**, **Repair**, and **Advanced Detach**. Bake changes loaded objects and dirties packages but never saves automatically. Save Bake Set saves exactly the manifest scope with the Layer checkpoint last. Rebase-retired/frozen packages stay in that scope across later Current/All bakes until their metadata changes and every output save succeeds; only then are one-shot retired paths pruned before the Layer checkpoint. If that checkpoint fails, the complete pre-save scope is restored in memory for a truthful retry.

Bake evidence has two independent compatibility axes: `Paper2DPlusLayerBakeVersion::CurrentManifestVersion = 1` for manifest structure and `CharacterLayerBakeCore::CurrentDigestVersion = 4` for hashing semantics. If either stored version is older, the bake set is stale and migrates only through explicit **Bake All**. If either is newer, the entire set is read-only: status may inspect it, but Bake, Save, Overwrite, Repair, Rebase, Detach, digest repair, and audit mutation are refused so an older plugin cannot reinterpret future data.

Status is content/ownership-derived: Never Baked, Up to Date, Needs Bake, Output Conflict, Detached, or Recovery Required, with separate Needs Save/Partial Save diagnostics and exact package paths. Detach freezes current output and releases matching management claims; it does not reverse-compose pixels into layers, restore old art, or delete generated assets.

### Runtime appearance and hybrid presentation

`FPaper2DPlusAppearanceDescriptor` is the sole committed runtime appearance. It contains a semantic version, the exclusive delivery mode, and a normalized complete `ActiveLayerIds` list in the asset's global Layer order. It contains no preset ID, actors, components, sprites, pixels, materials, cache keys, distances, visibility, or tiers.

`ApplyAppearancePreset`, `SetLayerActive`, `ResetToDefaultAppearance`, and `ApplyAppearanceDescriptor` all follow one commit order:

1. normalize/store the descriptor;
2. compose layer-specific hitboxes, sockets, and Frame Cues for gameplay;
3. emit one visual advisory;
4. publish the authority snapshot when opt-in replication is enabled.

Preview, manual visibility, recolor, cache state, priority, tier, and pending reason are presentation only and never replicate or become SaveGame authority. Dedicated servers keep descriptor/gameplay state and allocate no appearance visuals.

Hybrid rendering is opt-in and default-off through `UPaper2DPlusLayerRenderComponent::bEnableHybridRuntimeRenderer` (**Enable Hybrid Runtime Renderer**). Runtime Customizable actors with it disabled retain an exact all-live fallback; one actor never draws all-live and hybrid output together. The optimized path builds transient GPU render-target composites from resident cooked sprite geometry/textures, caches exact appearance+animation recipes under a byte budget, and hands off atomically at a matching key-frame boundary. It creates no persistent flipbook, sprite, texture, or package.

Every visual/gameplay consumer uses the asset's one global Layers array order. This keeps render composition, Independent Live selection, and paint-order-sensitive `Replace Lower` gameplay merges aligned. Runtime Customizable edit/save copies each Layer's `AuthoredAnimations` into cooked per-layer rows; packaged composition resolves the registered flipbook soft identity and applies Layer placement to boxes and sockets without a category-specific or compatibility fallback.

The hybrid backend validates the complete immutable recipe once before cache admission, including every frame's sprite/baked-texture references, cooked geometry, material, opacity, recolor, and texture requirements. Bounded frame builds then recheck only the selected frame—including actual RHI residency—instead of rescanning every frame, preventing animation-length-squared validation work. Unsupported recipes remain exact through the live fallback.

Most art uses `BaseComposite`; up to two declared `IndependentLive` channels may remain separately animated in the near tier. The far tier folds every visible layer into one complete composite. A one-plane base can preserve live art only as a back prefix and/or front suffix around its contiguous base interval. If the cap splits those edge runs, front-most channels are retained first, then only the outermost back channels; interior/excess channels fold into the base and art is never dropped. Impossible authored base/live interleaving remains a validation error.

`UPaper2DPlusAppearanceBudgetSubsystem` is one client-local world scheduler—never one appearance tick per actor. It assigns Descriptor Only, Far Composite, Near Composite, and Changing Live tiers under configured live-handoff, build-unit, measured preparation/submission-millisecond, independent-channel, cache-byte, distance, and frustum budgets. The shipped dual composite-work gate is independently capped at two units and a measured 0.300 ms of game-thread preparation/submission per frame; the derivation and rerun evidence live in the Crowd Benchmark. `Paper2DPlus.ShowAppearance` and **Get Appearance Budget Stats** expose aggregate pressure. See [Runtime Appearance](docs/runtime-appearance-guide.md), [Crowd Benchmark](docs/appearance-crowd-benchmark.md), and [Multiplayer Authority Contract](docs/authority-contract.md).

### Extraction, Aseprite, de-bake, and pixel drawing

- `SSpriteExtractorWindow` handles one texture (Island flood-fill or Grid; Grid's Columns/Rows can be auto-detected with the same `FSpriteExtractionUtils::DetectFrameGrid` Bulk uses, failing closed on a weak signal, and this window never pads); `SBulkSpriteExtractorWindow` handles multi-texture extraction, cross-sheet alignment, and optional de-bake groups with live Base/Overlay/Composite preview. Full-cell extraction stays blocked until every included current grid divides its texture into positive whole-pixel cells and all live cell sizes agree. Auto-pad aligns each source cell's MIDPOINT to its destination cell's midpoint - the same anchor the uniform trim bakes as the sprite pivot, so the two stages agree by construction (never anchor a trimmed cell on its bounding-box centre; the two diverge after a trim). It still records a delta for each original source cell, migrates sister-Profile metadata before accepting the padded textures, and retains recovery sidecars until a safe restore or explicit full-cell commit. Frame grids come from `FSpriteExtractionUtils::DetectFrameGrid` - a gutter rule (every internal boundary column empty, blank cells only as a capped trailing run) with a filename size hint, a twin rule for identical-dimension siblings, and same-frame-format folder consensus as tiebreaks; a BLEED TIER tolerates a few stray boundary pixels on trimmed art but is consulted only when no clean grid exists; rows split only on an explicit hint. - `FAsepriteImporter` parses `.ase/.aseprite`, preserves CharacterForge identity, frame durations, linked ("hold") cels, and additive layered reimport data. A Content Browser drop reaches the window through `AsepriteContentBrowserDrop` — an `FAssetViewDragAndDropExtender` that claims external drops carrying `.ase/.aseprite` files, converts the drop folder's VIRTUAL path (`/All/Game/…`) to the internal package path, hands the WHOLE list to the window in one call and sends any non-Aseprite files in the same drop down the ordinary import path. `UAsepriteFactory` still exists for the Import button / File > Import path: it parses nothing, hands the file to the window and returns `nullptr` + `bOutOperationCanceled = true` (the engine's no-error cancel shape). - **Section suggestions on import (Structure sections U4):** the row editor's **Preview Section Suggestions…** derives one-level Sections from that file's top-level folders through the pure `FLayerStructureController::DeriveSectionSuggestions` — no parser work, because `FCharacterLayer::LayerName` IS the `.ase` group path and the same strings sit pre-commit on `FBulkExtractorTextureState::AseLayerNames`. The proposal is previewed and edited (accept / rename / remove) before anything is written; the accepted set lives on the row and `FLayerStructureController::ApplySectionSuggestions` writes it. **THE RULE: the `LayerGroups` row and every member's `GroupId` go in ONE transaction** — `EnsureLayerAuthoringIdentity` invalidates a `GroupId` with no matching row and runs on every import, so writing one without the other silently un-sections everything on the next reimport. The apply is idempotent (Sections resolve by name, a layer moves only if it changes, a no-op opens no transaction and leaves the package undirtied), which is what lets `CommitAseSources` re-apply the accepted set after each row's import creates the layers a fresh import could not have had. Reimport never re-derives Sections: a curated assignment survives, a renamed layer carries its Section, and a new layer arrives ungrouped.
- **Live-edit propagation (TASK-186):** `FTextureWatcherService` initializes on `OnFEngineLoopInitComplete` — NEVER guard editor-service init on a bare `if (GEditor)` in `StartupModule`, GEditor is still null there and the service silently never runs (this exact bug made live reimport dead code from TASK-71 until 2026-08-20). The import stamps its context on the Layer Profile (`ImportOutputPath`/`ImportAssetPrefix`/`bImportOrganizeIntoSubfolders`/`ImportDisabledTagNames`); on a tracked .ase change the watcher re-runs the FULL `ImportAsLayeredAsset` pipeline (settings reconstructed, `ExistingLayerAsset` = the asset itself, profile = `BaseProfile`) so sheet/sprites/flipbooks/profile refresh in place and NEW tags become new flipbooks; context-less legacy assets keep the layer-only `FAsepriteReimporter` diff path. The watcher's `ProcessPendingChanges` iterates a COPY of each file's entries — the full re-run's tail calls `RefreshAssetMapping()`, which rebuilds the map mid-loop. The dialog's picker rows carry **New…** buttons (create-or-select a named Character Profile / Layer Profile at the output path — no engine modal), the Character Layer asset is labeled **Layer Profile** in this dialog, and the source copy lands FLAT in `<Project>/SourceArt/`.
- **Structural-diff reimport (TASK-189):** a reimport diffs the source STRUCTURALLY rather than guessing from names. `FAsepriteStructuralDiff` holds the pure decisions (rename pairing, removal disposition, the per-animation `AnimationSprites` merge, authored-data detection, content hashes); `AsepriteDiffApply` in `AsepriteImporter.cpp` applies them. **THE ORDER RULE: the diff applies BEFORE the pipeline writes** — every creator is FindOrCreate-in-place, so renaming first moves the sheet/sprites/flipbook and lets the creation pass refresh those same packages through the redirector; applying afterwards strands the old assets and duplicates the layer. That forces two phases: tags before the profile is populated (`AppendProfileEntriesFromImportResult` matches by NAME), layers before the per-layer materialisation. A rename resolves only when it is unambiguous, hashes are equal, no sibling source contributes the name, and the new name is unowned; anything else degrades to delete+add. Removed items carrying authored work are KEPT and reported, and backing assets are never deleted — only reported as orphans. Outcomes surface non-modally (notification + the **Aseprite Import** Message Log listing) because the watcher drives this path unattended, and a no-op reimport leaves the package undirtied.
- **Incremental reimport (TASK-192):** every write site is gated by `FAsepriteIncrementalWrite` (`AsepriteIncrementalWrite.h/.cpp`) — per-asset-class verdicts (Create / WriteGridChanged / WriteInputsChanged / WriteForced / SkipPayload) derived from STAMPS on the Layer Profile's `FAsepriteSourceContext` (`LayerContentHashes`, `CompositeContentHash`, `TagStructureHashes`, `NormalLayerContentHashes`, the stamped grid) plus Asset Registry existence. **Generated assets are NOT resident during a reimport** (`FindOrCreateAssetInPackage` is a `FindObject`), so gates never test residency, and absent stamps FAIL CLOSED to write. A sprite's pixel payload rides its sheet's verdict but existence never does (a deleted sprite always recreates); bounds-narrowing derives the tight box from the composited buffer in hand — replicating `FindTextureBoundingBox`'s strictly-greater alpha threshold, shrink order, and all-empty→1×1-bottom-right degenerate — and compares it against the serialized render/collision geometry (read via reflection), so an inside-the-silhouette recolor skips the per-sprite `InitializeSprite` rebuild (the measured ~94% of a full reimport: a whole-sheet `FAlphaBitmap` scan per sprite) while `ShrinkWrapped`/`Diced` geometry, unprovable from a bounding box, always rewrites. A byte-changed file producing no asset change still RESTAMPS — one dirtied package, the Layer Profile — or the startup reconcile would re-queue it forever. `bEnableAseLiveReimport` (**Project Settings → Paper2DPlus → Aseprite Import**, default on) gates the watcher's .ase branch and the startup reconcile, with an off→on transition re-running the reconcile; **Force Full Reimport** on the Layer Profile's Content Browser menu replays everything gates-bypassed (works with the setting off); every auto-reimport publishes the non-modal **Aseprite Import** Message Log audit page (`FAsepriteImportCostReport::DecisionLines`). `FAsepriteImportCostScope` + `UPackage::PackageMarkedDirtyEvent` count phases, writes/skips, and unique dirtied packages per reimport (one "Aseprite import cost (TASK-192)" summary log line); the opt-in `Paper2DPlusPerf.AsepriteIncremental` lane replays the measured six-layer shape fresh-vs-covered.
- **Source-in-project + offline propagation (TASK-183):** the dialog's **Keep .ase in project** option (default on) copies the source beside its generated assets and the Layer asset tracks the copy — `SourceAseFilePath` is stored PROJECT-RELATIVE (resolve only through `FAsepriteImporter::ResolveStoredAsePath`; a raw `ConvertRelativePathToFull` anchors to the binaries dir) with an MD5 stamp in `ImportedAseContentHash`. Both are exposed as hidden asset-registry tags (`Paper2DPlus.SourceAseFile`/`SourceAseHash`) so `FTextureWatcherService` maps every saved layer asset without loading it, loads lazily only when a file changes, accepts ADD as well as MODIFY events (git pulls arrive as delete+recreate), and — once the registry's initial scan completes — runs `ReconcileOfflineAseChanges()` to auto-reimport files whose content hash no longer matches their last-import stamp (edits pulled while the editor was closed). `FAsepriteReimporter` re-stamps the hash on every successful reimport.
- `FVariantDebake` plus `FBulkDebakeUtils` recover and materialize a shared base and per-variant residual overlays inside the Bulk Extractor. Accept writes every required output before changing the batch, validates `/Game` output paths and texture payloads, and keeps shared VFX sources excluded until their final accepted group reverts. The retained `Paper2DPlus.OpenDebakeVariants` command and Texture2D action both open this unified flow; `SDebakeVariantsWindow` no longer exists.
- The Flipbook Draw editor paints directly into a flipbook frame's source texture with its own model/canvas/tool panel and pure `FFlipbookPixelEdit` core. `FlipbookDrawCanvas.cpp` owns interaction/editing while `FlipbookDrawCanvasRendering.cpp` owns geometry and paint projection. Drawing tools include Pencil, Eraser, Dropper, Fill, Line, and outlined Rectangle; **Drawing Symmetry** reflects only new strokes/shapes, while **Frame Transform** explicitly flips existing pixels left/right or top/bottom, rotates 180°, nudges one pixel, or clears the frame. Shape previews and transforms each commit as one pixel-undo entry, and fixed frame dimensions never change. Committing pixels also re-derives that sprite's geometry and dirties the sprite package: tight, shrink-wrapped, and diced render *and* collision bounds are computed from the source alpha and then serialized, and the engine never invalidates them when a texture changes — so an edit that moves the art must re-derive them or the frame keeps drawing and colliding against its pre-edit bounds. Open it from **Content Browser → right-click a Paper Flipbook → Common → Paper2D+ Actions → Edit Frames (Paper2D+ Draw)…**; the sibling **Add to Character Profile Asset…** command shares that branded submenu, and the submenu plus both commands use distinct plugin-owned SVG icons from `Resources/Icons/`.

## Development Workflow

### Coordinate concurrent edits

Before editing, inspect and claim exact paths with `scripts/ai-file-guard.ps1`. Claims use a renewable 60-minute lease; run `touch -Agent <agent-name> -Session <stable-session-id>` before expiry. Use explicit `release` for scoped handoffs. Before any final response or session archive, always run `finalize -Agent <agent-name> -Session <stable-session-id>` so remaining claims are released and authenticated outstanding build subscriptions are detached.

Claims and requests record the host `session_id`. Claude binds it on `SessionStart` and exact-finalizes on true `SessionEnd`; Claude/Codex `Stop` is turn-scoped and intentionally does nothing. Codex has no safe archive hook, so explicit finalization is mandatory. Legacy overlong claims are still hard-capped at 60 minutes from their last touch. A nonterminal build subscription becomes detached after 10 minutes without a touch and cannot launch work while detached, but authenticated resubmission of the same stable request ID reconnects it; explicit cancel/finalize remains terminal. For a crashed or archived owner, verify with `status`, then use user-authorized exact recovery—`release -Id <claim-id> -Force`, or `finalize -HostSessionId <session_id>` when that identity is known—without unarchiving the old task or using an agent-wide wildcard.

It deliberately does not pass `-Unversioned`: BuildPlugin must stamp each packaged descriptor for the engine that compiled it. The wrapper derives `Major.Minor.0` from that engine's `Build.version` and fails unless the packaged `.uplugin` matches exactly. After UAT succeeds, it removes the guarded package's generated `Intermediate` tree, requires the descriptor/icon plus `Source`, `Binaries`, `Resources`, `Config`, and `Shaders`, rejects generated or private directories, and hashes the packaged `DefaultPaper2DPlus.ini` and `FilterPlugin.ini` against source. Descriptor byte/hash parity with source is intentionally not required because the per-engine stamp is the expected UAT mutation. A release result is complete only when its JSON records matching `expected_engine_version`/`packaged_engine_version`, `engine_version_verified: true`, and `release_content_verified: true`; never repair or restamp a package with an unreported manual copy, descriptor edit, or cleanup.

## Conventions and Non-Negotiable Boundaries

- **Stable identity, never array index:** picker selection uses object path/fallback identity; Layer source uses `LayerId`/`GroupId`; Effect membership uses flipbook path; Catalog rows use Character Profile path.
- **Animation Map access has three focused routes:** use `FindAnimationByExactTags` for ordinary single-animation lookup, including unrooted animations such as Idle. Transition inspection/resolution (`GetAnimationTransitionInfo`/`ResolveAnimationTransition`) is flipbook-keyed — Profile + current flipbook only, no group or chain-start inputs; a flipbook shared by multiple entries fails closed. `GetComboChainFlipbookAtIndex`/`GetComboChainFlipbookAtIndexByTags` resolve ONE combo step from the flagged opener (flipbook or exact tags) plus a game-owned counter (opener = index 0; the auto-derived main line via `Paper2DPlusComboChain::DeriveComboSpine` — the definitive start→Chain End line when an end is flagged, else the longest authored continuation; Index Out Of Range = the combo finished, with the chain length still reported; non-openers and dual-flagged openers fail closed) — use these instead of walking transitions phase-by-phase for combos. `GetComboChainLength`/`GetComboChainLengthByTags` (plus the boolean `HasComboChain` — true only for a flagged opener with a 2+-step countable line) are the direct "how long is this combo" queries (same opener keys, countable length out, failure clears the output). The boolean Chain End flag (`bIsChainEnd`) marks the main line's last COUNTABLE step — trailing recovery animations wired after it stay authored but are never indexed or counted. The ByTags routes match a Chain Start's authored `ChainTags` container (the chain's own identity) with PRECEDENCE over an animation's own tags; only when no chain container matches do they fall back to exact own-tag lookup. `GetComboOpenerFlipbooks` is the discovery route: every valid Chain Start's opener flipbook, group-tag-sorted then authored entry order. The boolean Chain Start flag replaces Root Numbers — chains are named by their opener move, and multiple flags per group mean multiple chains. Never infer chain starts (or ends) structurally — the flags are authored. Do not expose raw Tag Mappings or reintroduce random/first-match resolvers. The editor shows the derived numbering: a `#N` chip on Map chain nodes and a read-only "Combo" line in the details pane — both stamped from the same `DeriveComboSpine` derivation the Blueprint node uses.
- **Animation Map Blueprint menu organization:** the six combo-specific nodes live under `Paper2DPlus > Animation Map > Combo`; exact-tag lookup and the two transition nodes remain directly under `Paper2DPlus > Animation Map`.
- **Refresh is read-only:** search, filtering, source refresh, validation, coverage resolution, preview, and derived Combat/Catalog views must not dirty assets. The Catalog roster additionally takes no implicit writes at all — entries, group memberships, and expected tags change only through explicit Add / Remove / Suggest Companions / rail or tag-editor transactions, and registry events merely re-project saved rows.
- **One provider per source:** Profile/Character Baseline/Layer Cue and hitbox sources go through their provider seams; do not fork a reduced editor or composition implementation.
- **One fixed-publishing coordinator:** stage before mutation, recheck preconditions, commit atomically, retain evidence, save only through explicit Save Bake Set. Never reverse-compose managed output.
- **Exact bake fails closed:** require explicit `TF_Nearest` plus `TMGS_NoMipmaps`; do not flatten a custom material, transformed `Texture.Source`, alternate section, empty/non-manifold/ambiguous topology, or incompatible opacity approximately. Digest coverage/build settings, preserve full-cell output geometry, and send unsupported art to the live path.
- **Version and save scope are monotonic:** manifest v1 and digest v4 are independent; an older value requires explicit Bake All and a newer value makes the set read-only. Retired/frozen packages remain in Save Bake Set until outputs and the final Layer checkpoint are durable.
- **Descriptor before presentation:** committed runtime appearance updates gameplay first, visuals second, replication publication third. Local presentation can never block or rewrite authority state.
- **Presentation never replicates:** no composite texture, cache key, tier, distance, visibility, queue, recolor MID, or priority enters the network payload.
- **No persistent runtime composites:** hybrid output is transient GPU/cache state only. Never create appearance-specific content assets at runtime.
- **Bounded channels:** Base Composite carries frame-synchronous art; at most two Independent Live declarations are supported. Never omit art to satisfy a budget.
- **Network decisions use one seam:** route new behavior through `Paper2DPlusNetGating` and the component's resolved net context. Replication remains opt-in and default-off.
- **Validation uses the shared service:** preserve domain validators, adapt their results into `FPaper2DPlusValidationIssue`, and expose a navigation target only when the host can truthfully focus it.
- **Transactions:** use `FScopedTransaction` for designer edits. Keep selection/filter/preview state transient unless the UI explicitly labels it as saved authoring intent.
- **Slate structural changes are deferred:** do not rebuild/destroy the widget that is currently committing text or handling tab activation. Use active timers/queued switches where established.
- **Test helpers are file-unique:** Unreal unity builds combine `.cpp` files; generic helpers in anonymous namespaces can still collide.
- **Tag colors use one resolver:** call `UPaper2DPlusSettings::ResolveTagColor`; never seed/read the backing override list ad hoc.
- **Cross-version guards stay local:** retain runtime/editor module boundaries and established UE-version include/API guards.
- **Cue behavior lives on the Cue and must be stateless (v8.0.0, deliberate reversal):** a Cue Type may implement `OnCueTriggered` / `OnCueBegin` / `OnCueUpdate` / `OnCueEnd` in the one permitted event graph, and dispatch runs that behavior immediately BEFORE the listener broadcast at every site. This REPLACES the retired "Frame Cues are data only" boundary, which was deleted from this list in v8.0.0; the reversal was user-approved, not drift, and must not be reverted. Behavior executes on the SHARED asset-owned placement instance, so it must never write instance state — persistent state and every release still live on the receiver, which is also what covers the one gap in the End guarantee (a class-orphaned range gets its listener End and no behavior End). Everything the envelope refuses — extra graph families, non-declared functions, components, timelines, interfaces, delegate/replicated/accessor/non-persistent payload fields — stays refused at all four layers, and new behavior events are declared once in `Paper2DPlusFrameCueBehavior`.

## Compatibility and Historical Notes

The following behavior is intentionally retained for loading or migration, but is retired as the primary workflow:

- **Executable Frame Events:** `UPaper2DPlusFrameEvent*`, legacy arrays, and retained `FrameEvent` filenames remain as saved-data load inventory only. Nothing converts or dispatches those rows. The v8.0.0 Cue behavior events did not revive that hierarchy; new authoring and runtime delivery use `Paper2DPlusFrameCues::DispatchFrameTransition` from `Paper2DPlusFrameCueDispatch.h` only.
- **Superseded category-first Layer editor:** historical plans and solution docs retain its archaeology, but no compatibility tab, API, redirect, or runtime path remains. The generic Layer Workspace is the sole source editor.
- **Pre-v5 Layer schema:** earlier whole-body, category-first, and compatibility-era representations are historical migration archaeology only. Current authoring is schema v5 with generic Layers, stable identities, global order, complete presets/default, and two exclusive delivery modes; no compatibility API, redirect, or renderer remains.
- **Effect name/profile spawn resolution:** retained fields are inert legacy data — the migrations that read them were deleted in v8.0.0 with the six built-in Cue classes. Current Effect rows are soft-first flipbook-identity library membership. A Cue Type uses ordinary designer-authored variables and behavior; scalar soft Paper Flipbook variables participate in structural frame-zero warming without a marker or declaration. Blueprint Effect Profile queries return hard Flipbooks at explicit loading boundaries.
- **Old Combat three-tab editor:** Details/Attack Catalog/Score Preview was replaced by the focused workspace listed above. Combat remains advisory despite the richer editor.
- **Phase groups/custom slots:** removed. Animation identity is per-flipbook `EditorMeta.PhaseTag`, transition rows may override it for that edge, and chain-derived animation phase remains separate derived information.
- **Input-buffer grace settings:** the transition driver and buffer were removed. `InputBufferGraceFrames_DEPRECATED` and `BufferGraceFramesOverride_DEPRECATED` only absorb historical config/asset/JSON values and are neither exposed nor read.
- **Legacy parallel tag arrays:** retained deserialization aliases still migrate to current tag-mapping entries. **Embedded legacy effect rows do not:** they remain inert, never-converted inventory. Do not write new code against either deprecated representation.

Useful historical solution docs can still explain migration hazards, but when terminology conflicts, the current source and the designer guides in this file are authoritative.
